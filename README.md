# Simulador de Diagnóstico de Hardware — E.E.T.P. N° 468

Actividad educativa interactiva para el espacio curricular **Hardware IV (6.º año)** de la **E.E.T.P. N° 468**.

## Descripción

Simulador autocontenido en un único archivo `index.html` (sin dependencias externas, sin servidores, sin cookies) que guía al estudiante por el diagnóstico de una PC de escritorio que no enciende. El objetivo es practicar un protocolo ordenado de fallas: inspección visual y códigos POST, mediciones eléctricas, integridad de datos y pruebas de estrés.

## Fases de la actividad

1. **Inspección visual y códigos POST** — tarjeta POST USB.
2. **Mediciones físicas y eléctricas** — multímetro, osciloscopio y termografía.
3. **Integridad de datos y memoria** — MemTest86 y S.M.A.R.T.
4. **Pruebas de estrés** — Prime95, FurMark u OCCT.

Cada fase requiere una justificación técnica escrita de al menos **20 palabras** para avanzar.

## Cómo usarlo

1. Abrir `index.html` en cualquier navegador moderno (Chrome, Firefox, Edge, Safari).
2. Completar nombre y apellido.
3. Recorrer las cuatro fases y redactar las justificaciones.
4. Generar el informe final y elegir:
   - **Imprimir / Guardar como PDF** (`window.print()`).
   - **Copiar informe** al portapapeles (para pegar en Google Docs o Classroom).
   - **Descargar informe (.txt)** como archivo de texto plano.

## Privacidad

Todos los datos se procesan localmente en el navegador. No se envía información a ningún servidor, no se utilizan cookies ni servicios de analítica. El nombre y apellido solo se usan para encabezar el informe de la actividad.

## Publicación en GitHub Pages

1. Subir `index.html` y este `README.md` al repositorio.
2. Ir a **Settings → Pages** y seleccionar la rama `main` (carpeta raíz).
3. Reemplazar en el `<footer>` de `index.html` el enlace `https://github.com/USUARIO/simulador-diagnostico-hardware` por la URL real del repositorio.
